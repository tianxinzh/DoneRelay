## Launch sequence

First make one user succeed: validate clean setup and record a real Telegram question → phone reply → same running task continuation. Label any simulated example. Publish an alpha changelog with the tested commit and host versions; retain safety caveats.

Then submit to the appropriate directory after its gates pass. Share a small, useful write-up where project announcements are allowed: the problem, the real demo, exact setup, limits, and source. Disclose that you maintain DoneRelay. Avoid mass unsolicited issues, artificial stars, fake installs, and unsupported comparisons.

Encourage a star after delivering value, not as a prerequisite to use the project. Ask users for their host version and reproducible setup failures; those reports improve installation and retention more directly than keyword changes.

## Measurement

Record an actual baseline before promotion: stars, available repository traffic/referrers, install/setup issues, clean-install success, and confirmed directory status. Repeat measurements consistently and note access/retention limits of each analytics source. Treat stars and clicks as interest, not active users. Do not add tracking of private Telegram messages or approval contents to measure adoption.

Primary success criterion: a new user can install, send a harmless question, reply, and observe the correct result without sharing a secret. Search and star outcomes remain uncertain.
